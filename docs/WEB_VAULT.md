# 网页与 CLI / MCP 共用本地文件库

本地服务在同一地址提供网页和文件库接口。网页新增、编辑和导入保存到 `vault.json`；CLI / MCP 指向同一个 `--vault` 目录即可读取。原有普通网页和手机仍使用设备存储。

## 启动

需要 Node 24+。在项目根目录运行：

```powershell
cd app
npm ci
npx expo export --platform web
cd ..
.\baku-web.cmd --vault .\private\my-vault --port 8775
```

保持终端运行，打开输出的完整地址，例如 `http://127.0.0.1:8775/?local-vault=1#token=...`。地址含本次进程的访问凭证，勿公开。重启服务后使用新地址。终端显示完整库路径，界面显示库名及“已保存到文件库”。不带连接参数的页面仍是设备存储模式。

CLI 使用：

```powershell
.\baku.cmd status --vault .\private\my-vault --json
.\baku.cmd notes list --vault .\private\my-vault --json
```

MCP 配置的 `--vault` 使用相同绝对路径，`--root` 包含该库目录，配置见 [MCP.md](MCP.md)。网页服务不需要 MCP 进程才能运行。

## 数据与冲突

- 网页首次载入从文件库读取，不自动迁移或合并浏览器原有笔记。迁移请先从普通网页导出 JSONL，再导入目标库。
- CLI / MCP 更新后，网页刷新才读取最新快照；当前版本没有实时推送。
- 每次保存带基准 revision，所有写入共用文件锁及原子快照替换。旧页面不能覆盖新 revision。冲突时未保存内容保留在页面；先导出备份，再刷新并按需导入或重新编辑。
- 网络响应丢失后的相同快照重试不会增加 revision；服务停机或写入失败会显示失败，不切回浏览器存储。
- 连接模式关闭云同步入口；它是本地文件库会话，尚未连接云同步。
- 网页读写快照上限为 16 MiB。附件二进制、实时推送及远程访问未实现。

## 本地访问

仅监听 `127.0.0.1`，接口要求随机 Bearer 凭证，检查 Host 与 Origin，不开放 CORS。凭证位于 URL fragment，不随静态资源请求传输。静态服务只提供 `app/dist` 内文件，校验符号链接/目录联接后的路径；笔记库不会作为静态文件提供。它不是针对恶意本地进程的操作系统沙箱。

## 验证

自动测试通过真实 HTTP 服务调用网页使用的存储 adapter，并启动真实 stdio MCP 子进程：CLI 导入 → 网页读取/编辑 → MCP 读取 → MCP 导入 → 网页重新加载；覆盖并发冲突、响应丢失重试、非法快照、无凭证、异源、错误 Host 和静态目录联接越界。类型检查、lint 和网页构建另行执行。

这些是接口与存储验证；页面显示、实际输入操作仍需浏览器验收。
